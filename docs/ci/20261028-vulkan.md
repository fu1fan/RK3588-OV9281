# ELF2 Vulkan 支持与开发

原 rootfs 只有 EGL/GLES 的 Mali 库，没有系统级 Vulkan ICD。镜像构建现在使用 SDK 固定的 AArch64 GCC 10.3 交叉编译 Khronos Vulkan Headers、Loader、Tools 1.3.239，并安装独立的 Mali-G610 g24p0-10 Vulkan 驱动。

驱动来自 Rockchip libmali 镜像仓库提交 `ec78b74adc038f97cf173f4061fe3856efc0dc74`，下载内容通过 SHA256 锁定，随镜像保留 ARM 许可。它通过 `/usr/share/vulkan/icd.d/mali.json` 加载 `/usr/lib/libmali-vulkan.so`；已有的 EGL/GLES/GBM 库和内核驱动保持原样。构建后逐文件读回最终 ext4 验证 SHA256，另外输出同源 `vulkan-runtime.tar.gz` 安装包。

## 板上验收

```sh
vulkaninfo --summary
elf2-vulkan-test
```

验收程序只接受 ARM (`0x13b5`) Mali-G610 集成 GPU，创建计算管线并提交 SPIR-V，GPU 对 4096 个整数执行 `x * 3 + 7`。CPU 等待 fence 后逐项验证全部结果，错误或超时返回非零状态。仅能枚举设备、CPU 软件驱动或原样返回输入均不能通过。

开发阶段在当前 5.10.209、Mali g18p0 内核驱动的板上，独立加载 g24p0-10 已验证成功：Mali-G610、设备 `0xa8670000`、驱动 API 1.3.276，4096 个 GPU 计算结果全部正确。系统 Loader 提供的实例 API 为 1.3.239。此测试覆盖无窗口计算，不等同于 Vulkan Wayland 窗口呈现验收，也不代表执行过完整 Vulkan CTS。

## 开发方式

在 CNB 上交叉编译，在开发板运行。镜像包含头文件和链接用 Loader，但不安装板上原生 GCC。将构建的运行时包解压到开发机的 SDK 目录，例如 `/tmp/elf2-vulkan-sdk`：

```sh
mkdir -p /tmp/elf2-vulkan-sdk
tar -xzf elf2-*-vulkan-runtime.tar.gz -C /tmp/elf2-vulkan-sdk
export CROSS_COMPILE=/path/to/gcc-arm-10.3/bin/aarch64-none-linux-gnu-
"${CROSS_COMPILE}gcc" -O2 \
  /tmp/elf2-vulkan-sdk/usr/share/elf2-vulkan/elf2-vulkan-test.c \
  -I/tmp/elf2-vulkan-sdk/usr/include \
  -L/tmp/elf2-vulkan-sdk/usr/lib -lvulkan -o elf2-vulkan-test
glslangValidator -V system/vulkan/compute.comp -o compute.spv
spirv-val compute.spv
```

把程序和 shader 传到开发板，运行 `./elf2-vulkan-test ./compute.spv`。GLSL 编译器和 SPIR-V 校验工具在 CNB 构建镜像中提供。开发应用通过 `-lvulkan` 链接系统 Loader，无需链接私有 Mali 库，也无需设置 `VK_ICD_FILENAMES` 或 `LD_LIBRARY_PATH`。

`vulkaninfo` 构建为无窗口诊断工具；不包含 validation layers。若要验证窗口呈现、外部内存共享或与 EGL 混合使用，须额外进行对应应用级测试。
